## Stage 6 simulator risks and controls

- Double counting: E must exclude D/B0/Bnew, and D must exclude BNPL. This is an input accounting assumption, not something inferred from aggregate amounts. Future UI must label it clearly.
- Currency: one currency label, default AUD; no FX conversion or CFPB survey-code mapping. The caller must not mix currencies.
- Timing: monthly positive buffer can coexist with due-date shortfalls; no detailed schedule or fortnight-to-month conversion is implemented.
- Coverage: S divided by unchanged outflows assumes no new income; it is not actual depletion time. S is held fixed across independent scenarios.
- Contract interpretation: reducing B0 is a hypothetical assumption, not permission to lower contractual repayments.
- Numeric handling: exact rational core, finite decimal-string serialization, separately rounded display. RTI deltas use percentage points. Browser integration must respect these units and parse values explicitly.
- Valid zeros: zero income/outflows produce explained N/A for the relevant ratio; other defined values remain available. Negative buffer triggers an auditable arithmetic notice, with no risk bands or credit decisions.
- Separation: simulator imports no ML/data dependencies; no default probability or combined risk score. All stage-five calibration/subgroup concerns remain in the unchanged model card.
- Privacy: the general API does not log/save personal inputs. The demo exports only the explicitly fictional supplied case.

111 regression tests passed. These controls establish formula/engineering correctness, not user comprehension improvement; RQ2 still needs real-user evidence.
